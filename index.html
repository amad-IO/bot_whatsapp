Features

Everything you need
in one server.

A complete WhatsApp messaging infrastructure. Self-hosted, zero monthly fees.

01
👥

Multi-Staff Support

Each staff gets an isolated WhatsApp session identified by a free-form staff_id. No limit on number of accounts.

02
📋

Message Queue

Insert messages into MySQL and deliver via cron trigger. Supports text, PDF, and media. Auto-retry up to configurable max attempts.

03
🗓️

Scheduled Messages

Set scheduled_at on any queued message. The cron processor delivers only when the time arrives.

04
🔗

Outgoing Webhooks

Set WEBHOOK_URL to receive incoming messages and delivery ACKs (sent / delivered / read) pushed to your system instantly.

05
✅

Delivery Tracking

Real-time ACK events update each message status in DB: sent → delivered → read. Queryable via API or visible in dashboard.

06
📊

Real-time Dashboard

Socket.IO-powered unified dashboard: stats, live feed, send messages, manage queue, view incoming, edit templates — all in one page.

07
🔐

API Key Auth

Optional API key protection on all /api/* endpoints via x-api-key header, Bearer token, or query param.

08
🛡️

Rate Limiting

30 req/min limit on direct-send endpoints. Configurable random delay between queue messages to mimic human behavior and avoid WA bans.

09
📢

Broadcast

Send one message to hundreds of numbers in a single API call. Automatic delay between sends, per-number success/fail result returned.

10
📝

Message Templates

Store reusable message templates in DB. Retrieve via API or select from the dashboard. Supports create, update, delete.

11
💾

Session Persistence

LocalAuth saves sessions to disk. On server restart, all staff sessions reconnect automatically — no re-scan QR needed.

12
❤️

Health Check

Public /api/health endpoint returns DB status, uptime, and active client count. Ready for uptime monitors and load balancers.

How It Works

Two send modes —
immediate or queued.

Choose the mode that fits your workflow. Both modes are accessible via a simple REST API.

01

Immediate Send

  • 1POST to /api/send-text with staff_id + phone + message
  • 2Server validates number is registered on WhatsApp
  • 3Message sent instantly, DB updated, messageId returned
  • 4ACK events update status to delivered → read automatically

⚠ Requires WA client to be connected

02

Queue Mode

  • 1POST to /api/queue-text (or queue-pdf / queue-media)
  • 2Row inserted to wa_outgoing with status=pending
  • 3Cron calls /api/run-cron?token=SECRET every N minutes
  • 4Processor sends pending messages, updates status, retries on failure

✓ Works even if client connects after queueing

Quick Start

Running in
4 steps.

View on GitHub →
01
Clone & install
git clone https://github.com/amad-IO/bot_whatsapp.git
cd bot_whatsapp
npm install
02
Configure environment
cp .env.example .env
# Edit .env — set DB credentials and CRON_TOKEN
03
Create database
mysql -u root -p -e "CREATE DATABASE simrs_wa CHARACTER SET utf8mb4"
mysql -u root -p simrs_wa < schema-update.sql
04
Start server & connect
node server-new.js

# Open in browser:
# http://localhost:3030/main-dashboard.html  — Dashboard
# http://localhost:3030/qr-scanner.html      — Connect WhatsApp

Example: Queue a message
curl -X POST http://localhost:3030/api/queue-text \
  -H "Content-Type: application/json" \
  -H "x-api-key: your-api-key" \
  -d '{
    "staff_id": "staff1",
    "wa_number": "628123456789",
    "message": "Hello from WA Gateway!",
    "scheduled_at": "2025-12-31 08:00:00"
  }'

# Response:
# { "success": true, "id": 42 }
